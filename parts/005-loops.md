## 1. Go มี loop keyword เดียว: `for`

ตามที่กล่าวถึงไปแล้วใน Part 001 ว่าปรัชญา "less is more" ของ Go สะท้อนออกมาชัดเจนที่สุดในเรื่อง loop: **Go มี keyword สำหรับวนซ้ำเพียงตัวเดียวคือ `for`** ไม่มี `while`, ไม่มี `do-while`, ไม่มี `foreach` แยกต่างหากแบบภาษาอื่น

แต่ `for` ตัวเดียวนี้ **เขียนได้ 4 รูปแบบ** ที่ครอบคลุมทุกกรณีการวนซ้ำที่ภาษาอื่นต้องใช้หลาย keyword แยกกัน:

| รูปแบบ | Syntax | เทียบเท่าภาษาอื่น |
|---|---|---|
| Condition-only | `for condition { }` | `while (condition) { }` |
| Classic three-clause | `for init; condition; post { }` | `for (init; condition; post) { }` |
| Infinite | `for { }` | `while (true) { }` |
| Range-based | `for k, v := range collection { }` | `for (item : collection)` / `for item in collection` |

มาดูทีละรูปแบบ

---

## 2. รูปแบบที่ 1 — Condition-only (คล้าย `while`)

เมื่อเขียนแค่เงื่อนไขเดียวหลัง `for` (ไม่มี init/post) จะทำงานเหมือน `while` ในภาษาอื่น: วนซ้ำไปเรื่อยๆ ตราบใดที่เงื่อนไขยังเป็น `true`

```go
n := 5
for n > 0 {
	fmt.Print(n, " ")
	n--
}
fmt.Println()
```

ผลลัพธ์:

```
5 4 3 2 1
```

---

## 3. รูปแบบที่ 2 — Classic Three-Clause

รูปแบบที่คุ้นเคยที่สุดจากภาษาตระกูล C: `for init; condition; post { }`

```go
for i := 0; i < 5; i++ {
	fmt.Print(i, " ")
}
fmt.Println()
```

ผลลัพธ์:

```
0 1 2 3 4
```

- **init**: `i := 0` — รันครั้งเดียวก่อนเริ่มลูป (ตัวแปรที่ประกาศตรงนี้มี scope จำกัดแค่ในลูปเท่านั้น เหมือนหลักการ scope ที่เรียนใน Part 003 และ init-statement ของ `if` ใน Part 004)
- **condition**: `i < 5` — เช็คก่อนแต่ละรอบ ถ้า `false` ออกจากลูปทันที
- **post**: `i++` — รันหลังจบแต่ละรอบ ก่อนเช็ค condition รอบถัดไป

ทุกส่วนเป็น optional เขียนขาดบางส่วนได้ (เช่น `for i := 0; i < 5; { ... i++ }` หรือ `for ; i < 5; i++ { }`) แต่ในทางปฏิบัติถ้าจะละส่วนไหนออกทั้งหมด มักเขียนเป็นรูปแบบ condition-only หรือ infinite แทนเพื่อความอ่านง่ายกว่า

---

## 4. รูปแบบที่ 3 — Infinite Loop

ไม่เขียนอะไรเลยหลัง `for` คือลูปไม่มีที่สิ้นสุด ต้องมี `break` (หรือ `return`) ข้างในเพื่อออกจากลูป:

```go
count := 0
for {
	if count >= 3 {
		break
	}
	fmt.Print(count, " ")
	count++
}
fmt.Println()
```

ผลลัพธ์:

```
0 1 2
```

รูปแบบนี้ใช้บ่อยมากในโปรแกรมที่ต้องรันตลอดเวลา เช่น server loop, worker ที่รอรับงานจาก channel (จะเห็นเต็มรูปแบบใน Part 036 เรื่อง Goroutines) หรือ retry loop ที่ออกจากลูปด้วยเงื่อนไขที่ซับซ้อนกว่าจะใส่ในหัว `for` ได้สะดวก

---

## 5. รูปแบบที่ 4 — Range-based Loop

`for ... range` ใช้วนซ้ำผ่านโครงสร้างข้อมูลแบบ collection ทั้งหมด (slice, array, map, string, channel) และตั้งแต่ Go 1.22 ยังใช้กับจำนวนเต็มตรงๆ ได้ด้วย รูปแบบทั่วไป:

```go
for key, value := range collection {
	// ...
}
```

ค่าที่ `range` คืนกลับมาจะต่างกันไปตามชนิดของ `collection` — เราจะไล่ดูทีละชนิดในหัวข้อถัดไป

---

## 6. `range` over slice และ array

`range` บน slice หรือ array คืนค่าคู่ `(index, value)`:

```go
fruits := []string{"มะม่วง", "กล้วย", "ส้ม"}
for idx, fruit := range fruits {
	fmt.Println(idx, fruit)
}
```

ผลลัพธ์:

```
0 มะม่วง
1 กล้วย
2 ส้ม
```

ถ้าต้องการแค่ index ไม่สนใจค่า เขียนตัวแปรเดียวได้เลย:

```go
for idx := range fruits {
	fmt.Print(idx, " ")
}
// ผลลัพธ์: 0 1 2
```

ถ้าต้องการแค่ค่า ไม่สนใจ index ต้องใช้ **blank identifier** `_` แทนตำแหน่ง index (จะเจาะลึกเรื่อง `_` เพิ่มเติมใน Part 008):

```go
for _, fruit := range fruits {
	fmt.Print(fruit, " ")
}
// ผลลัพธ์: มะม่วง กล้วย ส้ม
```

`array` (ที่ขนาดตายตัว ตามที่จะเรียนละเอียดใน Part 006) ก็ใช้ `range` แบบเดียวกันเป๊ะ:

```go
numbers := [4]int{10, 20, 30, 40}
for i, v := range numbers {
	fmt.Println(i, v)
}
```

ผลลัพธ์:

```
0 10
1 20
2 30
3 40
```

> **ข้อควรระวังสำคัญ (จะเจาะลึกใน Part 006)**: เมื่อ `range` บน **array** ค่าที่ได้ (`v`) เป็น**สำเนา (copy)** ของ element เพราะ array เป็น value type ตัดสินใจแก้ `v` ในลูปจะไม่กระทบ array ต้นฉบับเลย ต่างจาก slice ที่ underlying array เป็นตัวเดียวกัน (แต่ก็ยังต้องเข้าใจว่า `v` จาก `range` เป็น copy เหมือนกันในทั้งสองกรณี ถ้าต้องการแก้ไขต้นฉบับต้องเข้าถึงผ่าน `collection[i]` โดยตรง)

## 7. `range` over map

`range` บน `map` คืนค่าคู่ `(key, value)`:

```go
ages := map[string]int{"Somchai": 25, "Suda": 30}
total := 0
for _, age := range ages {
	total += age
}
fmt.Println("total age:", total)
```

ผลลัพธ์:

```
total age: 55
```

> **ข้อควรจำที่สำคัญมาก**: **ลำดับการวนซ้ำ `map` ด้วย `range` ไม่การันตีลำดับที่แน่นอน** (Go จงใจทำให้สุ่มลำดับเพื่อป้องกันไม่ให้โปรแกรมเมอร์เผลอพึ่งพาลำดับที่ไม่ควรพึ่งพา) ถ้าต้องการลำดับที่คงที่ ต้องดึง key ออกมาใส่ slice แล้ว sort เอง — รายละเอียดเต็มรูปแบบของ map จะอยู่ใน **Part 007**

## 8. `range` over string (ได้ rune ไม่ใช่ byte)

ตามที่ทิ้งท้ายไว้ใน Part 003 ว่าการวนผ่าน string มี 2 วิธีที่ให้ผลต่างกัน — `for i := 0; i < len(s); i++` จะได้ `s[i]` เป็น **byte ทีละตัว** แต่ `for i, r := range s` จะได้ `r` เป็น **rune ทีละตัวอักษรตามหลัก Unicode** (จำนวน byte ต่อ rune ไม่เท่ากันเสมอไป):

```go
for i, r := range "Go๙" {
	fmt.Printf("index=%d rune=%c (%d)\n", i, r, r)
}
```

ผลลัพธ์:

```
index=0 rune=G (71)
index=1 rune=o (111)
index=2 rune=๙ (3673)
```

สังเกตว่า `index` เป็น **byte offset** ของแต่ละ rune ในสตริง (ไม่ใช่ลำดับที่ 0, 1, 2 ของตัวอักษร) — `'G'` และ `'o'` เป็น ASCII ใช้ 1 byte ต่อตัว ดังนั้น `๙` (เลขไทยที่ใช้ 3 byte ใน UTF-8) จึงเริ่มที่ index `2` (หลัง `G` กับ `o` รวม 2 byte) ถ้าตัวอักษรตัวถัดไปมีอยู่ index ของมันจะกระโดดไปที่ `2 + 3 = 5` ไม่ใช่ `3` เพราะ `range` นับ byte ของ UTF-8 จริงๆ นี่คือเหตุผลที่ **`range` เป็นวิธีที่ถูกต้องในการวนผ่านตัวอักษรภาษาไทยหรือ Unicode อื่นๆ** ต่างจากการ index ตรงๆ ด้วย `s[i]` ที่จะได้ byte ดิบทีละ byte ซึ่งจะตัดตัวอักษรหลาย-byte ขาดกลางตัว

## 9. `range` over channel

`range` บน `channel` จะรับค่าจาก channel ไปเรื่อยๆ **จนกว่า channel จะถูก `close()`** จึงจะหยุดลูปเองโดยอัตโนมัติ (เนื้อหาเต็มเรื่อง channel และ goroutine จะอยู่ใน Part 036-038 แต่ syntax ของ `range` เหมือนกับที่เรียนตรงนี้ทุกประการ):

```go
ch := make(chan int, 3)
ch <- 1
ch <- 2
ch <- 3
close(ch)

for v := range ch {
	fmt.Print(v, " ")
}
fmt.Println()
```

ผลลัพธ์:

```
1 2 3
```

ถ้า channel ไม่ถูก `close()` และไม่มีค่าใหม่ส่งเข้ามาอีก ลูป `range` จะ **ค้างรอตลอดไป (block)** — เป็นจุดที่ต้องระวังมากเมื่อเขียนโปรแกรม concurrent จริง

## 10. `range` over int (Go 1.22+)

Go 1.22 เพิ่มความสามารถใหม่ที่สะดวกมาก: **`range` ตรงๆ บนค่า integer** เพื่อวนซ้ำตั้งแต่ `0` ถึง `n-1` โดยไม่ต้องเขียน three-clause for แบบเดิม (ต้องมี `go 1.22` ขึ้นไปใน `go.mod` ตามที่อธิบายไว้ใน Part 002):

```go
for i := range 5 {
	fmt.Print(i, " ")
}
fmt.Println()
```

ผลลัพธ์:

```
0 1 2 3 4
```

เทียบเท่ากับการเขียนแบบเดิม `for i := 0; i < 5; i++`  แต่กระชับกว่า และถ้าไม่ต้องการใช้ค่า `i` เลย (แค่ต้องการวนซ้ำ N ครั้ง) ละตัวแปรได้เลย:

```go
repeatCount := 0
for range 3 {
	repeatCount++
}
fmt.Println("repeatCount:", repeatCount)  // 3
```

รูปแบบนี้เขียนแทน pattern เดิมที่ต้องเขียน `for i := 0; i < 3; i++ { ... }` ทั้งที่ไม่ได้ใช้ `i` เลย ทำให้โค้ดสื่อเจตนา "ทำซ้ำ N ครั้ง" ได้ตรงและอ่านง่ายขึ้นมาก

> **หมายเหตุเรื่อง version**: ถ้าโปรเจกต์ของคุณมี `go.mod` ที่ประกาศ `go` ต่ำกว่า `1.22` ฟีเจอร์นี้จะ**ใช้ไม่ได้** แม้ตัว Go toolchain ที่ติดตั้งจะเป็นเวอร์ชันใหม่กว่าก็ตาม เพราะ behavior ของภาษาถูกกำหนดโดย directive `go` ใน `go.mod` ตามที่อธิบายไว้ใน Part 002 ไม่ใช่ตามเวอร์ชัน `go` binary ที่ติดตั้งอยู่ในเครื่องเพียงอย่างเดียว

## 11. Loop Variable Semantics: การเปลี่ยนแปลงครั้งใหญ่ใน Go 1.22

นี่คือหนึ่งในกับดักที่โปรแกรมเมอร์ Go มือใหม่ (และแม้แต่มือเก๋า) เจอบ่อยที่สุดเมื่อรวม `for range` เข้ากับ `goroutine` — และเป็นเรื่องที่ **Go 1.22 เปลี่ยนพฤติกรรม default ไปเลย** จึงจำเป็นต้องเข้าใจทั้งสองแบบ

### พฤติกรรมแบบเก่า (Go 1.21 และก่อนหน้า)

ก่อน Go 1.22 ตัวแปรที่ประกาศใน `for` (ทั้ง three-clause และ range) **ถูกสร้างขึ้นแค่ครั้งเดียว** แล้วถูกนำมาใช้ซ้ำ (reuse) ในทุกรอบของลูป พูดอีกแบบ: `i` หรือ `v` ในหัว loop คือ**ตัวแปรตัวเดียวกันตลอดทั้งลูป** แค่ค่าถูกเขียนทับใหม่ทุกรอบ

ปัญหาเกิดขึ้นเมื่อ spawn goroutine ในลูปแล้ว goroutine นั้น**capture ตัวแปร loop โดยการอ้างอิง** (closure — จะเรียนเจาะลึกใน Part 009) เพราะกว่า goroutine จะได้ทำงานจริง (ถูก schedule) ลูปอาจวนไปไกลแล้ว ทำให้ทุก goroutine เห็นค่าล่าสุดของตัวแปรตัวเดียวกันหมด

ทดลองจริง — โปรเจกต์นี้มี `go.mod` ระบุ `go 1.21`:

```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	var wg sync.WaitGroup
	results := make([]int, 0)
	var mu sync.Mutex

	for _, v := range []int{1, 2, 3} {
		wg.Add(1)
		go func() {
			defer wg.Done()
			mu.Lock()
			results = append(results, v)
			mu.Unlock()
		}()
	}
	wg.Wait()
	fmt.Println(results)
}
```

ผลลัพธ์ (บนโปรเจกต์ที่ `go.mod` ระบุ `go 1.21`):

```
[3 3 3]
```

ทุก goroutine capture ตัวแปร `v` ตัวเดียวกัน กว่าจะได้รันจริง ลูปวนจบไปแล้วและ `v` มีค่าสุดท้ายคือ `3` ทุก goroutine จึง append ค่า `3` เหมือนกันหมด — **นี่คือบั๊กที่พบบ่อยที่สุดอันดับต้นๆ ในโค้ด Go รุ่นเก่า**

### พฤติกรรมแบบใหม่ (Go 1.22 ขึ้นไป)

Go 1.22 แก้ปัญหานี้โดยเปลี่ยนให้ **ตัวแปรที่ประกาศในหัว `for` (three-clause หรือ range) ถูกสร้างขึ้นใหม่ทุกรอบของลูป (per-iteration scoping)** พูดง่ายๆ คือแต่ละรอบมีตัวแปร `v` เป็นคนละตัวกันจริงๆ ไม่ใช่ reuse ตัวเดิม

รันโค้ด**เดียวกันทุกตัวอักษร** แต่เปลี่ยน `go.mod` เป็น `go 1.22`:

```
[1 2 3]
```

ตอนนี้แต่ละ goroutine capture ตัวแปร `v` คนละตัวที่ผูกกับค่าของรอบนั้นๆ โดยเฉพาะ ผลลัพธ์จึงถูกต้องตามที่คนส่วนใหญ่คาดหวังตั้งแต่แรก (ในตัวอย่างนี้ sort ผลลัพธ์ก่อน print เพราะลำดับที่ goroutine เขียนเสร็จยังไม่การันตี แต่ **ค่าที่ได้ครบทั้ง 1, 2, 3 ไม่ซ้ำกันแล้ว**)

### สรุปเปรียบเทียบ

| | Go ≤ 1.21 (`go.mod` ระบุ ≤ 1.21) | Go ≥ 1.22 (`go.mod` ระบุ ≥ 1.22) |
|---|---|---|
| ตัวแปรในหัว `for`/`range` | สร้างครั้งเดียว ใช้ซ้ำทุกรอบ | สร้างใหม่ทุกรอบ (per-iteration) |
| ผลเมื่อ closure/goroutine capture ตัวแปรนี้ | เห็นค่าตัวเดียวกัน (มักเป็นค่าสุดท้าย) | เห็นค่าของรอบตัวเองอย่างถูกต้อง |
| ต้อง workaround หรือไม่ | ต้อง (ดูด้านล่าง) | ไม่ต้องแล้ว |

### วิธีแก้ปัญหาบน Go เวอร์ชันเก่า (ยังจำเป็นถ้าโค้ดต้อง compatible กับ `go.mod` เก่า)

ถ้าจำเป็นต้องรองรับ `go.mod` ที่ระบุเวอร์ชันต่ำกว่า 1.22 (หรือแค่อยากเขียนโค้ดที่ชัดเจนไม่กำกวม) มี 2 วิธีมาตรฐานที่ใช้กันมานาน:

**วิธีที่ 1: ส่งค่าผ่าน parameter ของ goroutine โดยตรง**

```go
for _, v := range []int{1, 2, 3} {
	wg.Add(1)
	go func(val int) {
		defer wg.Done()
		mu.Lock()
		results = append(results, val)
		mu.Unlock()
	}(v) // ส่ง v เข้าไปเป็น argument ตอน spawn — ค่าถูกคัดลอกทันที ไม่ใช่ capture ตัวแปรร่วม
}
```

**วิธีที่ 2: สร้างตัวแปรใหม่ในลูปก่อน capture**

```go
for _, v := range []int{1, 2, 3} {
	v := v // ประกาศตัวแปรใหม่ชื่อเดียวกัน shadow ตัวเดิม เฉพาะ scope ของรอบนี้
	wg.Add(1)
	go func() {
		defer wg.Done()
		mu.Lock()
		results = append(results, v)
		mu.Unlock()
	}()
}
```

ทั้งสองวิธีนี้ยังคงเห็นได้ในโค้ด Go จำนวนมากที่เขียนก่อนปี 2024 (โดยเฉพาะ open source library ที่ต้อง compatible กับ Go เวอร์ชันเก่าไปอีกนาน) เมื่ออ่านโค้ดเก่าแล้วเจอ pattern `v := v` แปลกๆ แบบนี้ ตอนนี้ก็รู้แล้วว่ามันคือ workaround สำหรับปัญหา loop variable capture นี่เอง — และเรื่องนี้จะเจอเจาะลึกอีกครั้งพร้อม pattern การใช้ goroutine ที่สมบูรณ์ใน **Part 036 (Goroutines พื้นฐาน)**

## 12. Labeled break/continue ในบริบทของ loop

ใน Part 004 เราแนะนำ labeled break/continue ไปแล้วในบริบทกว้างๆ ของ control flow มาทบทวนอีกครั้งโดยเน้นเฉพาะการใช้งานกับลูปซ้อนกัน ซึ่งเป็นสถานการณ์ที่ใช้บ่อยที่สุด

ตัวอย่าง: ค้นหาคู่ตัวเลขในสอง slice ที่บวกกันได้ผลลัพธ์ตามที่ต้องการ แล้วหยุดค้นหาทันทีที่เจอ (ไม่ใช่แค่หยุด loop ชั้นใน):

```go
func findPair(a, b []int, target int) (int, int, bool) {
search:
	for _, x := range a {
		for _, y := range b {
			if x+y == target {
				fmt.Println("เจอคู่ที่ต้องการ:", x, y)
				break search
			}
			if x+y > target*2 {
				continue search // ข้าม y ที่เหลือทั้งหมดของ x ตัวนี้ ไปลอง x ตัวถัดไปเลย
			}
		}
	}
	return 0, 0, false
}
```

จุดสำคัญคือ `break search` และ `continue search` ควบคุม **loop ชั้นนอก (ที่มี label `search:`)** โดยตรง ไม่ใช่แค่ loop ชั้นในสุดที่ครอบมันอยู่ ทำให้เขียนตรรกะ "หยุดค้นหาทั้งหมดทันทีที่เจอคำตอบ" หรือ "ข้ามการวนของ `x` ตัวปัจจุบันไปเลย" ได้ตรงไปตรงมา โดยไม่ต้องใช้ flag ตัวแปร boolean เพิ่มเพื่อเช็คซ้อนหลายชั้นแบบภาษาที่ไม่มี label

ข้อควรจำ: label วางไว้เหนือ `for` ที่ต้องการอ้างถึงเสมอ (บรรทัดก่อนหน้าติดกัน) และ 1 loop จะมี label ได้เพียงชื่อเดียว แต่ 1 ฟังก์ชันมีหลาย label คนละชื่อกันได้ตามจำนวน loop ที่ต้องการควบคุมแยกกัน

## สรุปสิ่งที่ได้เรียนในบทนี้

- Go มี loop keyword เดียวคือ `for` แต่เขียนได้ 4 รูปแบบ: condition-only (คล้าย while), classic three-clause, infinite, และ range-based
- `range` บน slice/array ได้ `(index, value)`, บน map ได้ `(key, value)`, บน string ได้ `(byteIndex, rune)`, บน channel ได้ค่าจนกว่าจะ `close()`
- ตั้งแต่ Go 1.22 ใช้ `range` บนจำนวนเต็มตรงๆ ได้เลย เช่น `for i := range 5` แทน three-clause for แบบเดิม
- ลำดับการวน `range` บน `map` ไม่การันตี — ห้ามพึ่งพาลำดับใดๆ
- `range` บน string ให้ index เป็น byte offset และ rune ที่ถูกต้องตาม Unicode ต่างจาก index ตรงๆ ที่ได้ byte ดิบ
- **การเปลี่ยนแปลงสำคัญของ Go 1.22**: ตัวแปรในหัว `for`/`range` ถูกสร้างใหม่ทุกรอบ (per-iteration scoping) แก้ปัญหา closure/goroutine capture ค่าผิดที่เคยเกิดกับ Go เวอร์ชันก่อนหน้า — พฤติกรรมนี้ถูกกำหนดโดย `go` directive ใน `go.mod` ไม่ใช่เวอร์ชันของ toolchain ที่ติดตั้ง
- workaround แบบเก่า (`v := v` หรือส่งผ่าน parameter ของ goroutine) ยังพบได้ในโค้ดเก่า แม้จะไม่จำเป็นแล้วบน Go 1.22+
- Labeled break/continue ควบคุมลูปที่ซ้อนกันหลายชั้นได้แม่นยำ มีประโยชน์มากในการค้นหา/หยุดการทำงานข้ามหลายชั้นของลูป

## แบบฝึกหัดท้ายบท

1. เขียนโปรแกรมพิมพ์ตาราง 1 ถึง 12 ของเลข 7 โดยใช้ classic three-clause for
2. เขียนโปรแกรมเดียวกับข้อ 1 แต่เปลี่ยนมาใช้ `range over int` (Go 1.22+) แทน แล้วเทียบว่าโค้ดกระชับขึ้นแค่ไหน
3. เขียนฟังก์ชันที่รับ string ภาษาไทยที่มีทั้งตัวอักษรและวรรณยุกต์ แล้วใช้ `range` วนพิมพ์ทีละ rune พร้อม byte index ของมัน สังเกตว่า index กระโดดข้ามกี่ byte ต่อ 1 ตัวอักษร
4. จำลองสถานการณ์ loop variable capture: เขียนโปรแกรมที่ spawn goroutine ในลูป `range` บน slice ของตัวเลข 5 ตัว โดยตั้งใจสร้าง `go.mod` สองเวอร์ชัน (`go 1.21` กับ `go 1.22`) รันเทียบผลลัพธ์ทั้งสองแบบ แล้วอธิบายว่าทำไมผลต่างกัน
5. แก้ปัญหาจากข้อ 4 บนสมมติฐานว่าต้อง compatible กับ `go 1.21` โดยใช้ทั้งสองวิธี (`v := v` และส่งผ่าน parameter ของ goroutine) แล้วยืนยันว่าได้ผลลัพธ์ถูกต้องทั้งคู่
6. เขียนฟังก์ชันค้นหาตัวเลขในตาราง 2 มิติ (slice ของ slice) ที่มีค่าตรงกับเป้าหมาย โดยใช้ labeled break เพื่อหยุดการค้นหาทั้งสองชั้นทันทีที่เจอ แล้วทดสอบว่าเมื่อเจอค่าที่ต้องการ loop หยุดจริงโดยไม่วนต่อ
